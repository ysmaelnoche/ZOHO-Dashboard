# TVS Philippines CRM Dashboard

The [project brief](docs/PROJECT_BRIEF.md) preserves the original requirements. The Daily Operations and Executive dashboards serve Philippine Central CRM and leadership in the shared TVS ASEAN Zoho CRM Plus Enterprise organization in the India data center. The dealer portal dashboard is a separate project phase.

- Build custom-coded Zoho CRM Home Page Dashboard widgets with internal Zoho hosting, TypeScript, HTML, CSS, the official CRM JavaScript SDK and project-local ZET. Use direct Home widget placement and use Canvas only if required as a container. Verify APIs, widget conventions and CLI compatibility against official Zoho documentation.
- Keep presentation, dashboard types, environment configuration and data adapters modular and reusable. Prefer lightweight tooling and avoid unnecessary dependencies or backend services.
- Keep local preview login-free with clearly labeled synthetic data. Exclude real identities, contact details, confidential records and credentials from fixtures and packages.
- Require verified module and field API names, relationships and permissions before enabling live reads. Enforce Philippine access via authenticated CRM permissions and record sharing. Browser filtering cannot enforce authorization. Keep Indonesian and other out-of-scope records outside the integration.
- Obtain separate authorization for CRM access, live widget creation, org configuration changes and deployment. Protect existing workflows, integrations, modules, layouts, dashboards, functions and permissions. Document authorization-dependent work before execution. Keep secrets out of source and public URLs free of customer information.
- Use readable, strict TypeScript and accessible, responsive UI. Prefer compact tables, neutral surfaces, restrained TVS branding, clear typography and consistent spacing. Reserve red for critical exceptions, amber for warnings and green for verified success. Each metric informs a decision and each alert corresponds to an operational issue. Avoid decorative effects, illustrations and misleading visualizations.
- Verify type checking, tests, standalone preview, ZET validation and ZIP contents before handoff. Document tooling limitations and maintain reproducible install, build, test and packaging instructions. Preserve existing work and obtain authorization before pushing or taking irreversible action.
